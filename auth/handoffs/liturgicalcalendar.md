```bash

# No client secret — PKCE.
```

⚠ UTI validates Zitadel tokens **locally** rather than delegating to the API's `/auth/me`, which
verifies with the API's HS256 service alone and rejects Zitadel tokens by design. That is why UTI's
app must issue **JWT** access tokens: an opaque one has no verifiable structure, so UTI cannot
authenticate the user at all.

⚠ **Common mistake:** putting the API Backend's `ZITADEL_CLIENT_ID` in the frontend's env. The frontend's PKCE login flow will fail because the API app uses `PRIVATE_KEY_JWT` auth, not the PKCE/authorization_code flow. **They are two distinct apps with distinct client_ids; do not share them.**
