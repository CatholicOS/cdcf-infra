# BibleGet — auth handoff

Generated by `setup-zitadel.sh --provision-bibleget` (+ `--provision-bibleget-website`
on local).

Consumer repo: [`BibleGet-I-O/endpoint`](https://github.com/BibleGet-I-O/endpoint)
(the v4 API) and, later, the BibleGet website (Next.js).

## What is provisioned

| | |
| --- | --- |
| Org | `BibleGet` (`--create-orgs`) |
| Project | `BibleGet`, *Assert roles on authentication* on |
| Roles | `bibleget_admin` — the endpoint's `/admin/*` routes |
| Apps | `BibleGet Website` (Web, `client_secret_post`, JWT access tokens, role assertion), **local only** for now |

No API app: the endpoint never calls introspection. It verifies the access
token as an RS256 JWT against `$ZITADEL_ISSUER/oauth/v2/keys`, requires
`iss == ZITADEL_ISSUER` and the Project id in `aud`, and reads roles from
`urn:zitadel:iam:org:project:roles`. Developers need no role: any signed-in
user with a verified email may create projects.

## Endpoint configuration

```
ZITADEL_ISSUER=https://auth.catholicdigitalcommons.org
ZITADEL_AUDIENCE=<ZITADEL_PROJECT_ID from the provisioner output>
```

Staging (`query.bibleget.io/dev`) and production share the instance, so they
share the Project and the same `ZITADEL_AUDIENCE`.

## Verified on a local instance (Zitadel v4.15.0, 2026-11-18)

A user token from the website app (scopes `openid email profile`):

- is an RS256 JWT whose `aud` holds the app's client id **and the Project id**
  (no `urn:zitadel:iam:org:project:id:…:aud` scope needed);
- carries both roles claims (`…:project:roles` and `…:project:<id>:roles`);
- does **not** carry `email` / `email_verified` — those are only in the ID
  token and at `/oidc/v1/userinfo`.

## Grant an admin

Zitadel console → `BibleGet` Org → Projects → `BibleGet` → Authorizations →
New → the user → `bibleget_admin`.
